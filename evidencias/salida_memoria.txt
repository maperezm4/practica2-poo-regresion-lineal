4. VECTOR DE LinearRegression EN MEMORIA DINAMICA
--------------------------------------------------
(a) new LinearRegression[5]
    arreglo[0] -> 0x560648ec1478
    arreglo[1] -> 0x560648ec1500
    arreglo[2] -> 0x560648ec1588
    arreglo[3] -> 0x560648ec1610
    arreglo[4] -> 0x560648ec1698
    sizeof(arreglo) (puntero) : 8 bytes
    Tamano real del bloque    : 5 * 136 = 680 bytes
    Distancia entre elementos consecutivos: 136 bytes (coincide con sizeof(LinearRegression):
    los objetos son contiguos en el heap)

(b) std::vector<LinearRegression> vec(5)
    sizeof(vec)       : 24 bytes (el objeto vector en el stack: 3 punteros)
    vec.size()        : 5
    vec.capacity()    : 5
    Memoria del buffer: 680 bytes en el heap
    Direccion de vec (stack): 0x7fffb72f9f70 | Direccion de vec.data() (heap): 0x560648ec1730

JUSTIFICACION DEL TAMANO:
  * sizeof(arreglo) = 8 porque es un PUNTERO, no el bloque.
  * El bloque reservado es N * sizeof(LinearRegression) = 680 bytes,
    mas unos pocos bytes ocultos de metadatos del asignador
    (y el conteo de elementos que new[] guarda para delete[]).
  * Eso tampoco incluye lo que cada objeto reserve despues en sus
    vectores internos al entrenarse.

6. MAPA DE MEMORIA DEL PROCESO (resumen de direcciones)
--------------------------------------------------
  Global/estatica : 0x560617c7b160
  Heap (new)      : 0x560648ec1310
  Heap (new[])    : 0x560648ec1478

De menor a mayor direccion: codigo < datos globales < heap < stack.
El heap crece hacia arriba y el stack hacia abajo.
NOTA: con ASLR activo las direcciones cambian en cada ejecucion,
pero el ORDEN relativo de las regiones se mantiene.

--------------------------------------------------
7. LIBERACION DE MEMORIA
--------------------------------------------------
Memoria dinamica liberada correctamente.
Reglas aplicadas: cada new con su delete, cada new[] con su
delete[], y los punteros se dejan en nullptr para evitar
punteros colgantes (dangling pointers) y dobles liberaciones.
El std::vector libera su buffer solo (RAII) al salir del ambito.

--------------------------------------------------
DESGLOSE DEL TAMANO DE LinearRegression
--------------------------------------------------
sizeof(LinearRegression) = 136 bytes

Composicion aproximada (plataforma de 64 bits):
  weights_      std::vector<double>  : 24 bytes
  bias_         double               : 8 bytes
  learningRate_ double               : 8 bytes
  epochs_       size_t               : 8 bytes
  tolerance_    double               : 8 bytes
  solver_       enum class           : 4 bytes
  scalingType_  enum class           : 4 bytes
  scaleCenter_  std::vector<double>  : 24 bytes
  scaleSpread_  std::vector<double>  : 24 bytes
  trained_      bool                 : 1 bytes
  iterationsRun_ size_t              : 8 bytes
  finalCost_    double               : 8 bytes

JUSTIFICACION:
  * sizeof() mide SOLO el tamano estatico del objeto, no los datos
    que sus vectores reservan en el heap.
  * Cada std::vector ocupa 24 bytes (tres punteros de 8 bytes:
    inicio, fin y fin de capacidad), sin importar cuantos elementos
    almacene. Los elementos viven aparte, en memoria dinamica.
  * El compilador aplica ALINEACION (padding): el bool de 1 byte se
    rellena hasta completar un multiplo de 8, que es la alineacion
    exigida por los double y los punteros.
  * Por eso la suma ingenua de los miembros puede ser menor que
    sizeof(LinearRegression).

Fin del analisis de memoria.
