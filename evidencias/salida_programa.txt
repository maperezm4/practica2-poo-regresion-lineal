PARTE 2 - ANALISIS DE MEMORIA
==================================================

1. MEMORIA GLOBAL
   modeloGlobal   -> direccion: 0x55ef42509160   tamano: 96 bytes
   Se crea antes del main y vive hasta que termina el programa.

2. MEMORIA LOCAL (stack)
   modeloLocal1   -> direccion: 0x7ffc7d5f2020   tamano: 96 bytes
   modeloLocal2   -> direccion: 0x7ffc7d5f2080   tamano: 96 bytes
   Se borran solos cuando termina la funcion.

3. MEMORIA DINAMICA (heap)
   modeloDinamico -> direccion: 0x55ef6ffe36e0   tamano: 96 bytes
   El puntero esta en el stack, en: 0x7ffc7d5f2010
   El puntero ocupa 8 bytes (solo guarda la direccion).
   Hay que borrarlo con delete o queda ocupando memoria.

4. VECTOR DE OBJETOS EN MEMORIA DINAMICA
   arreglo[0] -> 0x55ef6ffe77c8
   arreglo[1] -> 0x55ef6ffe7828
   arreglo[2] -> 0x55ef6ffe7888
   arreglo[3] -> 0x55ef6ffe78e8
   arreglo[4] -> 0x55ef6ffe7948

   sizeof(arreglo) = 8 bytes  <- es el tamano del PUNTERO, no del arreglo
   Tamano real = 5 * 96 = 480 bytes
   Las direcciones van de 96 en 96 bytes, o sea que los objetos estan pegados uno tras otro.

5. DE DONDE SALE EL TAMANO DEL OBJETO
   sizeof(RegresionLineal) = 96 bytes

   Lo que tiene adentro:
     pesos         (vector) : 24 bytes
     bias          (double) : 8 bytes
     tasaAprendizaje(double): 8 bytes
     iteraciones   (int)    : 4 bytes
     medias        (vector) : 24 bytes
     desviaciones  (vector) : 24 bytes

   Cada vector ocupa 24 bytes sin importar cuantos numeros guarde,
   porque por dentro son 3 punteros. Los numeros estan en otro
   lado de la memoria, no dentro del objeto.

   Ademas el compilador rellena huecos para que todo quede
   alineado de a 8 bytes, asi que el total puede ser un poco
   mayor que la suma de las partes.

6. LIBERACION DE MEMORIA
   Memoria liberada. Cada new con su delete y cada new[] con su delete[].
   Los punteros quedan en NULL para no usarlos por accidente.

Fin del programa.
